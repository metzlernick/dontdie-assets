LEFT ARM PRODUCTION ARCHITECTURE IS LOCKED:
- one generation pass for up to four current briefs
- 2400×2560 sheet; 4×4; 600×640 logical cells
- tiny finished cosmetic exemplar is the visual scale/style authority
- hero context screen-right; complete cosmetic screen-left
- clean white zero-contact separation
- no generated grip, hidden geometry, or AI reconstruction pass
- replacement should occupy approximately the SAME OR SMALLER total visual mass as the exemplar
- the exemplar is NOT merely a position marker
- permanent bias: WHEN UNCERTAIN, SMALLER
- slightly undersized source art is preferred because Illustrator enlargement is easy
- production priority: FINISHED-EXEMPLAR SCALE/LOCATION → SIMPLIFY DETAIL TO FIT SCALE → EXACT IDENTITY → POSE/DESIGN/VARIATION
- IF SIZE AND DETAIL CONFLICT: KEEP SMALL SIZE AND REMOVE/SIMPLIFY DETAIL
- real-world size and comparison-asset size do not override production scale
- approved references may control palette/design language/silhouette vocabulary, but not generation scale

MANDATORY CONFLICT GATE — LEFT ARM
Before creating any LEFT ARM production package, compare every user instruction against the locked controller.

If the user asks for or implies a change to scale, exemplar authority, hero placement, zero-contact, sheet geometry, detail hierarchy, grip/hand interaction, or reconstruction workflow:
1. STOP before producing files.
2. Explain the exact conflict and likely failure mode.
3. Offer a safe rewording that preserves the design intent without modifying the canonical production system.
4. Proceed only after the brief is non-conflicting.

Do not silently reinterpret a conflict.
Do not invent a one-off exception.
Do not redesign the controller for a specific row.
Do not let phrases such as "large," "same scale as," or "similar size to" alter canonical LEFT ARM generation scale.

CATEGORY OVERRIDE — ARMOR / OUTFITS
If the requested category is ARMOR / OUTFITS, MUST ALSO read:
- ARMOR_OUTFIT_PRODUCTION_WORKFLOW.md
- current canonical-derived hero geometry/substrate reference
- current canonical hand reference

ARMOR / OUTFIT PRODUCTION ARCHITECTURE IS LOCKED:
- Stage A = registered complete outfit generation on canonical hero
- optional Stage A.5 = cape control only
- Stage B = faithful isolation of the approved upstream result
- final cleanup / registration = Illustrator

STAGE A RULES:
- use canonical-derived geometry/hand references plus current text briefs
- do NOT include old generated dressed-character calibration sheets as visual references
- preserve near-canonical body proportions and pose
- preserve viewer-left lowered shoulder → upper arm → elbow → forearm → wrist → hand chain
- preserve viewer-right raised arm chain
- Don't Die hands = THREE FINGERS + ONE THUMB = FOUR TOTAL DIGITS
- never add a fifth digit or rogue lower knuckle/finger
- do not turn the hero into a shorter/wider generic chibi body

OPTIONAL STAGE A.5 — CAPE CONTROL:
Use only when cape state must change after Stage A.
Per row/cell select one mode:
- KEEP
- REMOVE
- RESTYLE

Stage A.5 may change cape state only.
It must preserve non-cape outfit design, body proportions, pose, both arm chains, both four-digit hands, feet, pedestal, X/Y, and row/column mapping as closely as possible.
For REMOVE, do not invent substitute rear cloth, wings, scarf masses, coat tails, or a replacement cloak.
For RESTYLE, modify only the cape and keep its established attachment/scale/flow controlled.

STAGE B RULES:
- use approved Stage A directly when no A.5 is required
- use approved Stage A.5 when cape control was required
- isolate, do not redesign
- remove hero/head/pedestal/context
- keep complete outfit, both hands, sleeves/armwear, footwear, details, and exact upstream cape state
- preserve X/Y, scale, proportions, arm chains, hand geometry, and row/column assignment
- reconstruct only the minimum hidden garment edge required for continuity

DO NOT USE:
- post-isolation generative Stage B.5 cape removal
- approximate spatial/color cape masks on flattened Stage-B PNGs as a general cape-removal method

Those approaches were tested and caused global redraw drift or damaged non-cape artwork.
