LEFT ARM PRODUCTION ARCHITECTURE IS LOCKED:
- one generation pass for up to four current briefs
- 2400×2560 sheet; 4×4; 600×640 logical cells
- tiny finished cosmetic exemplar is the visual scale/style authority
- hero context screen-right; complete cosmetic screen-left
- clean white zero-contact separation
- no generated grip, hidden geometry, or AI reconstruction pass

- permanent bias: WHEN UNCERTAIN, SMALLER

ARMOR / OUTFIT PRODUCTION ARCHITECTURE IS LOCKED AND COMPLETE:

Initial briefs + cape manifest

STAGE A RULES:
- use canonical-derived geometry/hand/arm references plus current text briefs
- preserve near-canonical body proportions, pose, both arm chains, feet, and hand scale
- Don't Die hands = THREE FINGERS + ONE THUMB = FOUR TOTAL DIGITS
- never add a fifth digit or rogue lower knuckle/finger
- default to simple flat canonical-hero-like rendering: large color regions, low color count, restrained interior lines, minimal micro-detail
- pixel/8-bit/heavily geometric rows should be placed last when possible
- old generated dressed-character calibration sheets are NOT geometry authorities

DESIGN-ONLY EXCEPTION:
If the user explicitly wants an already-approved outfit idea reused, a prior approved sheet may be included only as a clearly labeled DESIGN-ONLY reference.
It may guide identity/palette/material distribution/silhouette family, but NEVER anatomy, registration, hand geometry, scale, or body proportions.
For simplification passes, preserve the approved idea while removing secondary detail and colors rather than redesigning it.

CAPE MANIFEST — MANDATORY:
Every armor batch carries explicit row metadata from the initial brief:
- KEEP = intended cape remains
- NONE = row is capeless; Stage B removes rear cape/context mass rather than guessing visually
- RESTYLE = use localized Stage A.5 cape redesign before Stage B

The user should NOT need to restate cape state at Stage B.
The same manifest travels downstream.

OPTIONAL STAGE A.5:
Use only when Stage A visually disagrees with cape metadata or RESTYLE is requested.
It changes cape state only; it is not a general outfit-redesign or registration pass.

STAGE B — DESTRUCTIVE ISOLATION ONLY:
- use approved Stage A directly, or approved A.5 if used
- image = literal outfit artwork authority
- manifest = cape-ownership authority
- remove head/face/hair/ears/exposed non-outfit hero anatomy/context
- remove ALL headwear when body outfit only is requested
- remove the ENTIRE wooden pedestal/platform in every cell
- pedestal top, rim, outline, highlight, shadow, and fragments must all be absent
- former pedestal area remains white; NEVER reconstruct hidden feet/boots/peg geometry into it
- rows marked NONE contain no cape/rear-cloak mass
- rows marked KEEP retain their approved cape
- preserve only visibly existing approved outfit art
- preserve structural outfit features such as requested peg legs
- NEVER complete hidden collars, necklines, sleeves, capes, boots, wraps, or peg geometry
- newly exposed regions remain white
- treat cells independently; no semantic borrowing

STAGE B ACCEPTANCE:
PASS only if:
- outfit identities/hands remain faithful
- cape state matches manifest
- pedestal is completely absent in all 16 cells
- no hidden geometry was reconstructed
- no cross-row contamination

Raw Stage-B scale/X/Y drift does NOT fail isolation by itself. Do not regenerate merely to chase registration drift.

DETERMINISTIC REGISTRATION — MANDATORY AFTER STAGE B:
- Stage A/A.5 = coordinate and scale authority
- Stage B = artwork/isolation authority
- solve every logical cell independently
- uniform scale + X/Y translation only
- no rotation, non-uniform stretch, warp, redraw, inpainting, or semantic changes
- raw download dimensions may differ slightly from Stage A; do not trust them as canonical
- rebuild final sheet EXACTLY 1920×2560 with EXACT 480×640 cells
- whole-sheet resize is NOT a substitute for per-cell restoration

DO NOT USE:
- post-isolation generative Stage B.5
- visual guessing of cape ownership
- approximate flattened color/spatial cape masks as the general solution
- hidden geometry reconstruction
- prompt counter-bias to compensate for Stage-B drift
- repeated Stage-B regeneration just to fix scale/X/Y
